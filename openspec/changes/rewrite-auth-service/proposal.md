## Why

`old.mindustrytool.features.auth.AuthService` (494 LOC) is singleton auth orchestrator that owns its own `Request` (`Config.API_v4_URL`), mixes token storage/JWT expiry, session fetch, login dialog/polling, logout, periodic refresh, and Arc UI (`authWindow`, `AuthLoginDialog`). The new codebase already has `mindustrytool.services.MindustryAuthProvider` (token-only, 192 LOC) and typed `mindustrytool.services.MindustryTool` facade for `/auth/*`, but the two are disconnected: `MindustryAuthProvider` still does raw `api.post("auth/app/refresh").withoutAuth().json(...)` instead of delegating to `MindustryTool`, has no session/login lifecycle, no events, and old code still imports `old.mindustrytool.features.auth.AuthService` (20+ call sites). A full rewrite is needed to replace `old AuthService` with a split `mindustrytool.*` implementation that keeps `MindustryAuthProvider` as the preserved `AuthProvider`, separates logic from UI, uses only `auth.*` i18n keys, and funnels all HTTP through `MindustryTool`.

## What Changes

- **BREAKING** Introduce `mindustrytool.services.AuthService` as pure-logic singleton in `src/mindustrytool` (session cache, `fetchSession`, `login`/`pollLoginToken`, `logout`, `init` timer, `SessionLoadEvent`/`LoginEvent`/`LogoutEvent` via `arc.Events`) and `mindustrytool.ui.AuthOverlay` (or `mindustrytool.services.AuthUi`) as pure-UI singleton (`authWindow` overlay, `AuthLoginDialog`, `SessionLoadEvent` rendering). Delete `old.mindustrytool.features.auth.AuthService` with no delegating shim.
- Rewrite both parts to delegate every HTTP call through `MindustryTool` typed methods: `getSession()`, `getLoginUri()`, `pollLoginToken(loginId)`, `logout(accessToken, refreshToken)`, `refreshToken(refreshToken)` — no direct `Request` construction for `auth/*` endpoints in either part. `AuthService` logic owns `UserSession currentSession` and `CompletableFuture<Void> loginFuture`; UI owns `AuthLoginDialog`/`Table authWindow`.
- Preserve `mindustrytool.services.MindustryAuthProvider` unchanged as the sole `AuthProvider` (`refreshIfNeeded()`, `getAccessToken()`, JWT `exp<60s`, deduplicated `refreshFuture`, `Core.settings` keys `mindustrytool.auth.*`) and keep `MindustryTool` wiring `api = Request.builder().baseUrl(Config.API_URL).authProvider(MindustryAuthProvider.getInstance()).build()`. `AuthService` logic reads/writes tokens via `Core.settings` directly (same keys) or via `MindustryAuthProvider` accessors, but does not implement `AuthProvider` itself and does not own a second `Request`.
- Port session lifecycle in `AuthService`: `fetchSession()` → `MindustryTool.getSession()`, `isLoggedIn()` (settings-only `has(ACCESS)&&has(REFRESH)`), `currentSession` cache, event firing. Port login flow: `login()` → `MindustryTool.getLoginUri()` + `AuthOverlay` dialog + `MindustryTool.pollLoginToken(loginId)` with `Duration.ofMinutes(5)` expiry, `KEY_LOGIN_ID`/`KEY_LOGIN_EXPIRY` handling, clipboard/URI open, and deduplicated `loginFuture`. Port `logout()` → `MindustryTool.logout(accessToken, refreshToken)` with `withoutAuth`+`Authorization: Bearer` preserved.
- Port UI in `AuthOverlay`: `initUi()`/`init()` builds `wholeViewport`/`authWindow` (`Styles.black6`, `Touchable.childrenOnly`, `Vars.ui.menuGroup` via `Core.app.post`), subscribes `SessionLoadEvent` to render states (loading/error/guest/authenticated), handles `AuthLoginDialog.showLoading()`/`showLoginUrl(loginUrl)` and `startLoginUI` (success/failure toasts). Logic `AuthService.init()` calls `fetchSession()`, schedules `Timer.schedule(300s)` periodic refresh, and resumes unexpired `loginId` via `pollLoginToken` in background — no UI imports in logic class.
- Clear all legacy i18n keys used by auth and add new namespaced keys under `auth.*`: e.g. `auth.login`, `auth.logout`, `auth.login.dialog-title`, `auth.login.cancel`, `auth.login.loading`, `auth.login.login-url`, `auth.login.copied`, `auth.login.success`, `auth.login.failed`, `auth.login.timeout`, `auth.logout.confirm-title`, `auth.logout.confirm-message`, `auth.session.loading`, `auth.session.error`, `auth.session.retry`. Every new key gets a mandatory comment above it in `assets/bundles/bundle.properties` explaining context and placeholders.
- No delegation pattern: `old AuthService` is deleted outright; `MindustryAuthProvider` is not made to delegate to `AuthService` nor vice versa.

## Capabilities

### New Capabilities
- `auth-service`: Split auth implementation in `mindustrytool.*` — `AuthService` (logic: session/login/logout/refresh coordination via `MindustryTool`, events, timers, no UI) + `AuthOverlay`/`AuthUi` (UI: `authWindow`/`AuthLoginDialog`/`SessionLoadEvent` rendering) with zero `old.*` imports and all user-visible text under `auth.*` bundle keys; `MindustryAuthProvider` preserved as `AuthProvider`.

### Modified Capabilities
- `http-client`: Keep `MindustryAuthProvider implements AuthProvider with deduplicated refresh` requirement unchanged (preserved class still owns its `Request api = Request.builder().baseUrl(Config.API_URL).authProvider(this).build()` and JWT logic); add note that new `AuthService` does NOT replace it and does NOT own a `Request` for `auth/*`.
- `api-models`: Auth DTOs/events (`UserSession`, `AuthTokenResponse`, `LoginUriResponse`, `SessionLoadEvent`, `LoginEvent`, `LogoutEvent`) must exist under `mindustrytool.models`/`mindustrytool.events` with no `old.*` reference; `JsonUtils` remains JSON helper.

## Impact

- Affected code: `src/mindustrytool/services/MindustryAuthProvider.java` (preserved, no merge), `src/mindustrytool/services/AuthService.java` (new logic, ~200-300 LOC, no UI imports), `src/mindustrytool/ui/AuthOverlay.java` + `src/mindustrytool/ui/AuthLoginDialog.java` (new UI, ~150 LOC), `src/mindustrytool/services/MindustryTool.java` (unchanged wiring to `MindustryAuthProvider`), `src/mindustrytool/models/**`/`events/**` (auth DTOs/events), `assets/bundles/bundle.properties` (clear legacy auth keys, add `auth.*` with comments), `src/old/mindustrytool/features/auth/**` (deleted, no shim), `src/old/mindustrytool/Main.java` (init now calls `AuthService.getInstance().init()` + `AuthOverlay.getInstance().init()` if needed), 20+ legacy features (`StorageService`, `ChatStreamClient`, etc.) migrated off `old AuthService` in follow-on.
- APIs/Systems: `Config.API_URL` only (drop `Config.API_v4_URL`), endpoints `/auth/session`, `/auth/app/login-uri`, `/auth/app/login-token`, `/auth/app/refresh`, `/auth/app/logout` via `MindustryTool`; `Request` with/withoutAuth unchanged.
- Dependencies: No new deps; uses `arc.Core.settings`/`arc.Events`/`arc.util.serialization.Jval` (JWT only in preserved provider), `mindustrytool.services.Request`+`MindustryTool`, `mindustrytool.utils.JsonUtils`, Arc scene2d (`Table`, `Styles`, `Icon`, `BaseDialog`, `Vars.ui`).
- Breaking: `old.mindustrytool.features.auth.AuthService` removed without delegate; `auth.*` i18n namespace replaces cleared generic keys (`@login`/`@loading`/`@error` etc. no longer used by auth); `AuthService` no longer implements `AuthProvider` (callers needing provider use `MindustryAuthProvider.getInstance()`).
